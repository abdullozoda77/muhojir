# Muhojir — документация каждого файла

**Язык:** [English](DOCUMENTATION.md) · [Тоҷикӣ](DOCUMENTATION.tg.md) · Русский

Muhojir — платформа для таджикских мигрантов в России: документы и их сроки, цена патента для каждого региона,
пошаговые инструкции, настоящие вакансии с «Работы России» с чёрным списком работодателей от работников,
тренировка экзамена, новости законов, уведомления в реальном времени, AI-помощник, авиабилеты между Таджикистаном
и Россией и карта полезных мест.

В коде нет комментариев: всё, что его объясняет, находится в этом файле. Каждый раздел ниже — одна папка; для
каждого файла написано, **для чего он нужен**, и таблица его функций, классов и компонентов с тем, что они делают.

## Из чего сделан проект

| Часть | Технология |
|---|---|
| API | FastAPI + Pydantic, всё асинхронно |
| База данных | SQLAlchemy 2 (asyncio), миграции Alembic; SQLite (или PostgreSQL через `DATABASE_URL`) |
| Вход | почта + пароль, 6-значные коды на почту, JWT (access 60 мин, refresh 30 дней, меняется и отзывается при выходе) |
| Админ-панель | SQLAdmin на `/admin/`, роли `migrant` / `editor` / `admin` |
| Уведомления в реальном времени | WebSocket `/ws/notifications/` (+ Redis между процессами) |
| Фоновые задачи | Celery + Redis: письма, импорт вакансий (06:00), напоминания (06:30), оповещения о цене билетов |
| Внешние сервисы | «Работа России» (вакансии), Travelpayouts/Aviasales (билеты), OpenStreetMap (места), Gemini / Claude (помощник) |
| Сайт | React 19, React Router 7, Vite, Tailwind CSS, motion, иконки lucide, MapLibre; устанавливаемое PWA с офлайн-режимом |
| Языки | сайт написан на таджикском; `translations.js` содержит русский перевод |

## Как проходит запрос

1. Сайт на React (`frontend/src`) обращается к `/api/...` через `api.js`, который добавляет JWT-токен.
2. `app/main.py` передаёт запрос роутеру из `app/routers/`; `app/core/deps.py` находит пользователя по токену.
3. Роутер проверяет тело запроса схемой из `app/schemas/`, читает и пишет таблицы из `app/models/`, для большой
   логики использует `app/services/` и отвечает JSON (списки постранично — `app/core/pagination.py`).
4. Долгая работа (письма, импорт, напоминания) уходит в Celery (`app/tasks.py`, `app/worker.py`).

## Запуск, тесты, выкладка

```bash
.venv/bin/alembic upgrade head        # таблицы + содержимое
cd frontend && npm run dev            # сайт :5175, API :8002
.venv/bin/python -m pytest            # тесты
```

Выкладка: соберите сайт на ноутбуке (`npm run build`), скопируйте `frontend/dist` на сервер и выполните там
`SKIP_BUILD=1 bash deploy/update.sh` (забирает код, обновляет базу данных и перезапускает сервисы).

## Где комментарии остались

Только в тексте, который не является комментарием к коду: `.env.example` и `alembic.ini` (инструкция для того,
кто их заполняет), шаблон `alembic/script.py.mako`, шаблоны `.env` и nginx, которые `deploy/setup.sh` пишет на
сервере, и инструкции AI-помощника в `app/assistant/knowledge.py` (это строки, которые читает модель).
Страницы API `/swagger/` и `/redoc/` больше не показывают длинные описания эндпоинтов: они теперь здесь.

### `app/db/session.py`

**Для чего:** Подключение к базе данных. В SQLite lower() знает только латиницу, поэтому поиск «москва» не находил бы «Москва»; он заменён на lower() из Python, который знает любой алфавит (кириллица, таджикский). ilike() в SQLAlchemy на SQLite — это lower(x) LIKE lower(y), поэтому любой поиск не зависит от регистра. PostgreSQL это не нужно.

| Имя | Вид | Что делает |
|---|---|---|
| `get_db()` | async-функция | Одна сессия базы данных на один запрос. |

### `app/db/types.py`

**Для чего:** Время хранится в UTC. У SQLite нет часовых поясов и он возвращает naive datetime, поэтому этот тип всегда отдаёт aware datetime в UTC — одинаково на SQLite и PostgreSQL.

| Имя | Вид | Что делает |
|---|---|---|
| `utcnow()` | функция | Текущее время в UTC. |
| `UTCDateTime` | класс | Тип столбца даты и времени в UTC. |
| &nbsp;&nbsp;↳ `process_bind_param(value, dialect)` | метод | Перед записью переводит время в UTC. |
| &nbsp;&nbsp;↳ `process_result_value(value, dialect)` | метод | Добавляет прочитанному времени пояс UTC. |

### `app/routers/auth.py`

**Для чего:** Регистрация и вход по почте и паролю: 1. POST /api/auth/register/ {email, password, full_name} -> аккаунт создан, 6-значный код уходит на почту; 2. POST /api/auth/verify-email/ {email, code} -> почта подтверждена, выдаются JWT-токены; 3. POST /api/auth/login/ {email, password} -> JWT-токены (только после подтверждения почты). Забыли пароль: POST password/forgot/ {email} отправляет код, POST password/reset/ {email, code, password}. resend-code/ {email} снова отправляет код регистрации. Дальше: token/refresh/, logout/, profile/, notifications/. Вход через Google: GET google/ -> {client_id}, POST google/ {credential} -> JWT-токены.

| Имя | Вид | Что делает |
|---|---|---|
| `check_password_rules(password, email)` | функция | Ошибка, если пароль слабый. |
| `logged_in(user, status)` | функция | Ответ с токенами и данными пользователя. |
| `jsonable(data)` | функция | Превращает данные в JSON. |
| `email_code(db, email, purpose)` | async-функция | Отправляет код, если с прошлой отправки прошло больше минуты. Бросает ApiError (429 — подождите / 503 — почта не работает). |
| `use_code(db, email, code, purpose)` | async-функция | Проверяет код; верный код срабатывает только один раз. Бросает ApiError, если он неверный или старый. |
| `user_by_email(db, email)` | async-функция | Находит пользователя по почте. |
| `register(data, db)` | async-функция · `POST /api/auth/register/` | Шаг 1 регистрации: почта, пароль и имя. Аккаунт ждёт подтверждения почты. |
| `verify_email(data, db)` | async-функция · `POST /api/auth/verify-email/` | Шаг 2 регистрации: код из письма. Подтверждает почту и выполняет вход. |
| `resend_code(data, db)` | async-функция · `POST /api/auth/resend-code/` | Снова отправляет код регистрации (только неподтверждённым аккаунтам). |

### `app/services/live.py`

**Для чего:** Уведомления в реальном времени: каждая вкладка браузера с вошедшим пользователем держит открытым WebSocket (/ws/notifications/?token=...). При нескольких процессах сервера (и воркере Celery, который делает напоминания) события идут через Redis (REDIS_URL): каждый процесс слушает и доставляет во вкладки, подключённые к нему. Без Redis всё остаётся в этом процессе (разработка). Проблема здесь не должна ломать сохранение самого уведомления, поэтому ошибки только записываются в лог.

| Имя | Вид | Что делает |

| `Hub` | класс | WebSocket-подключения каждого пользователя. |

| &nbsp;&nbsp;↳ `remove(user_id, socket)` | метод | Убирает закрытую вкладку. |
| &nbsp;&nbsp;↳ `deliver(user_id, message)` | метод | Отправляет сообщение во вкладки пользователя в этом процессе. |
| &nbsp;&nbsp;↳ `publish(user_id, message)` | метод | Отправляет сообщение во все процессы (через Redis) или сразу. |
| &nbsp;&nbsp;↳ `listen()` | метод | Запускается вместе с приложением, если задан REDIS_URL: доставляет события из всех процессов во вкладки этого. |

### `app/services/places.py`

**Для чего:** Настоящие места из OpenStreetMap (© OpenStreetMap contributors, ODbL) через серверы Overpass, для 30 регионов, где живёт больше всего мигрантов (`REGIONS`: название → ISO-код, например `RU-TA`; регион ищется по коду ISO3166-2, поэтому не зависит от того, как его название записано в OSM), и 12 видов мест (`SELECTORS`: migration, medical, notary, translation, embassy, mosque, food, halal, money, hostel, market, photo). Места снова находятся по их id в OSM, поэтому повторный импорт их обновляет. Места, предложенные пользователями, импорт никогда не трогает.

| Имя | Вид | Что делает |
|---|---|---|
| `query(region, selector)` | функция | Запрос Overpass для одного поиска (одного селектора) внутри одного региона. |
| `fetch_one(client, region, selector)` | async-функция | Спрашивает серверы Overpass по очереди, ожидая дольше после каждого ответа «занят» (15, 60 с); возвращает элементы или бросает последнюю ошибку. |
| `fetch(client, region, category, pause, log)` | async-функция | Выполняет все поиски категории по одному (маленькие запросы проходят лимиты времени серверов) и объединяет результаты без повторов; неудачный поиск записывается в лог, остальные всё равно используются. |
| `_clean(value, limit)` | функция | Одна строка текста без лишних пробелов, обрезанная до длины столбца. |
| `place_fields(element, region, category)` | функция | Поля Place из элемента OSM (название, адрес, координаты, телефон, сайт, часы работы); None, если нет названия или координат. |
| `save(db, element, region, category)` | async-функция | Создаёт место или обновляет место с тем же id в OSM; возвращает "created", "updated" или "skipped". |
| `import_places(db, regions, categories, pause, log)` | async-функция | Весь импорт: регионы по названию или ISO-коду (по умолчанию все 30), все категории; возвращает счётчики. Запуск: `python -m app.cli import-places [--region RU-TA] [--category hostel]`; Celery запускает его каждое воскресенье в 03:00. |

Объявления кадровых агентств пропускаются (частый способ обмана мигрантов), а имена и телефоны контактных лиц не копируются: люди откликаются на странице-источнике (external_url).

### `frontend/src/components/Assistant.jsx`

**Для чего:** AI-помощник: чат в углу каждой страницы.
